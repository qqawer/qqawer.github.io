## 前言

这篇笔记记录我学习 Transformer 时的真实困惑。第一次读教程的时候，Q/K/V、位置编码、Mask、多头注意力这些概念全都似懂非懂：公式能看懂，代码能跑通，但合上书说不清它们到底解决了什么问题。所以我没有按教程的章节顺序写，而是按"当时哪里卡住了"来组织，每个小节 = 当时的疑问 + 现在的一句话回答，方便以后快速复习。

主要参考资料：

- [《Transformers 库快速入门》](https://transformers.run)（Hugging Face Transformers 中文教程）
- [How-to-use-Transformers](https://github.com/jsksxs360/How-to-use-Transformers)（该教程的配套代码仓库）
- Vaswani et al., *Attention Is All You Need*（2017）

## 0. 先建立一个整体认知

一句话版本：**Transformer 是一种用"自注意力"代替 RNN/CNN 来建模序列的神经网络架构**；而 Hugging Face 的 Transformers 是一个 Python 库，专门用来加载、微调基于该架构的各种预训练模型——两者只是名字相同。

技术脉络（快速复习）：

1. Word2Vec 提供**静态词向量**，但解决不了多义词问题；
2. ELMo 用双向 LSTM 根据上下文**动态调整**词向量；
3. 2017 年 Google 提出 Transformer，用注意力机制一步到位建模全局依赖，而且可以并行计算；
4. GPT、BERT 基于 Transformer 确立"预训练—微调"范式；
5. 把 Transformer 规模做大，就成了今天的大语言模型（LLM）。

## 1. Transformer 到底是一个模型，还是一个架构？

**当时的困惑**：BERT 叫 Transformer，GPT 也叫 Transformer，它们长得很不一样，到底谁才是"那个模型"？

**现在的回答**：Transformer 首先指 2017 年论文《Attention Is All You Need》提出的**架构**（编码器 + 解码器 + 自注意力层），它不是一个具体的模型。BERT、GPT、T5 都是"基于 Transformer 架构"的具体模型，分别只用了编码器、只用了解码器、两者都用。Hugging Face 的 Transformers 库只是恰好继承了架构的名字，本质是一个模型工具箱。

记忆锚点：**架构是图纸，模型是按图纸造出来的具体产品，库是生产线。**

## 2. 注意力不是能"看"整句话吗，为什么还需要位置编码？

**当时的困惑**：自注意力里每个词都能和其他所有词交互，句子顺序难道不是天然就被考虑到了吗？

**现在的回答**：恰恰相反，注意力机制本身**对顺序完全不敏感**。`QK^T` 计算的是词与词两两之间的相似度，输出是"按相似度权重对 V 加权求和"，本质上是在做集合操作。如果把 "I love you" 的词序打乱，模型看到的每个词的注意力权重分配几乎不变——它无法区分 "love" 是第 2 个词还是第 3 个词。

所以需要**位置编码**把"第几个位置"的信息注入到词嵌入里。常见方案：

- **可学习位置嵌入**：BERT 的做法，位置向量也是训练参数；
- **正弦/余弦编码**：原论文的做法，静态模式，不需要学习；
- **RoPE（旋转位置编码）**：通过旋转矩阵把相对位置信息编码进 Q/K，是现在 LLM 的主流方案；
- **ALiBi**：直接在注意力分数上按相对距离加惩罚项，长度外推能力强。

记忆锚点：**注意力管"谁和谁相关"，位置编码管"谁在哪个位置"，两者缺一不可。**

## 3. Q、K、V 到底是什么？为什么叫"查询/键/值"？

**当时的困惑**：公式里 Q、K、V 三个矩阵长得一模一样，为什么要分三个？名字还取得这么奇怪。

**现在的回答**：用"查资料"类比最容易理解：

| 角色 | 类比 | 作用 |
| --- | --- | --- |
| Query（查询） | 你提出的问题 | "我现在想找什么信息？"由当前词决定 |
| Key（键） | 资料上的标签 | "我是不是你想找的内容？"负责和 Q 算相关度 |
| Value（值） | 资料正文 | 每个词真正携带的语义内容 |

流程：Q 和所有 K 做点积 → 得到相关度分数 → softmax 归一化成权重 → 对 V 加权求和，得到当前位置更新后的表示。

自注意力中 Q = K = V = 同一序列，但**不是直接用原始向量**：它们会分别乘上三个不同的线性映射矩阵 $W^Q, W^K, W^V$，把原始嵌入投影到不同的空间，让"提问、标签、内容"成为三种不同视角。

缩放点积注意力的公式：

$$\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^{\top}}{\sqrt{d_k}}\right)V$$

## 4. 为什么要除以 $\sqrt{d_k}$？点积不会太大吗？

**当时的困惑**：直接用点积当相似度不行吗？除以 $\sqrt{d_k}$ 是哪里冒出来的？

**现在的回答**：这是训练稳定性工程，不是玄学。假设 Q、K 的每个分量独立且均值 0、方差 1，那么点积的方差正好是 $d_k$——向量维度越高，点积数值就越大、越"夸张"。softmax 对很大的输入会饱和，梯度趋近于 0，模型就学不动了。

除以 $\sqrt{d_k}$ 后，点积的方差被拉回 1 左右，softmax 的输入分布更平稳，梯度更健康。**缩放因子不是拍脑袋定的，而是为了让方差保持常数。**

## 5. softmax 之后为什么还要乘 V？注意力权重本身不够吗？

**当时的困惑**：权重不是已经表示"该看谁"了吗？乘 V 这一步的意义是什么？

**现在的回答**：注意力权重只是一份"看谁多少"的比例表，**本身不包含任何词的内容**。真正构成输出的是 V 的加权和：

$$\text{输出}_i = w_{i1}v_1 + w_{i2}v_2 + \dots + w_{in}v_n$$

所以注意力机制的完整理解是：**按相关度在 V 上做加权平均**。这也是为什么输出向量的维度和输入保持一致（都是 $d_v$），可以把注意力层看成一种"软性的、可微的检索"。

## 6. 为什么单头注意力不够？"多头"多在哪里？

**当时的困惑**：教程里自己实现注意力时，跑出来每个词都最关注"自己"（分数矩阵对角线上最大），这看起来不是很有用。

**现在的回答**：当 Q = K 为同一份嵌入时，词和自己的点积天然最大，因为完全相同；但实际任务里**相关词往往比相同词更重要**。比如理解 "time flies like an arrow" 里的 flies，需要去看 time 和 arrow，而不是只看 flies 自己。

单头注意力只能学到一种"相似度"；多头注意力用 $h$ 组不同的线性投影把 Q/K/V 映射到 $h$ 个子空间，每个头负责关注不同方面的关系（语法、指代、语义、词序……），最后把各头的输出拼接起来再过一层线性变换。BERT 有 12 个头，每个头维度 $768 / 12 = 64$。

记忆锚点：**多头 = 多组并行的缩放点积注意力，等于让模型从多个角度看问题，再综合结论。**

## 7. 三种 Mask：padding、因果、交叉，别搞混

**当时的困惑**：教程里一会儿出现 mask，一会儿把分数填成 `-inf`，到底在防什么？

三种 Mask 的对比：

| Mask | 用在哪 | 作用 |
| --- | --- | --- |
| **Padding Mask** | 编码器/解码器的注意力 | 批处理时把长度补齐的填充 token 屏蔽掉，防止模型关注无意义的位置 |
| **因果 Mask（下三角）** | 解码器的自注意力 | 保证第 $t$ 个位置只能看到前 $t$ 个位置，防止"看到未来"的信息泄露 |
| **交叉注意力（Cross-attention）** | 解码器的第二层注意力 | Q 来自解码器，K、V 来自编码器输出，解码器可以看源序列全部内容，无因果限制 |

两个关键细节：

1. **为什么用 `-inf` 而不是 0**：softmax 之后 $e^{-\infty} = 0$，被屏蔽的位置权重正好归零；如果直接填 0，$e^0 = 1$，那些位置依然会分到非零权重。所以"禁用"必须用 `-inf`。
2. **训练和推理的区别**：训练时为了并行计算，会把完整的目标序列一次送入解码器，靠下三角 Mask"假装"是逐词生成的；推理时没有未来词，只能真正地逐 token 生成，把新生成的词不断拼回输入。

## 8. 编码器、解码器、编码器-解码器，怎么选？

**当时的困惑**：为什么 BERT 不能生成文本？为什么 GPT 什么任务都能干？架构到底有什么区别？

| 架构 | 注意力方式 | 典型预训练任务 | 擅长任务 | 代表模型 |
| --- | --- | --- | --- | --- |
| **纯编码器** | 双向：每个词能看到全句 | MLM（遮盖词预测） | 理解类：分类、NER、抽取式问答 | BERT、RoBERTa |
| **纯解码器** | 因果：只能看过去 | CLM（预测下一个词） | 生成类：续写、对话、代码 | GPT、Llama、Qwen、DeepSeek |
| **编码器-解码器** | 编码器双向 + 解码器因果 | 破坏-重建（T5）、去噪（BART） | 翻译、摘要、生成式问答 | T5、BART、M2M-100 |

**BERT 不能生成的根源**：双向注意力在生成时存在信息泄露——预测第 $t$ 个词时它已经"看到"了后面的词，而生成时后面的词根本还不存在。虽然可以改造，但远不如解码器架构自然，所以主流生成模型都用 Decoder-only。

**GPT 为什么"什么都会一点"**：因为生成式任务可以把理解类任务也转成"续写"——把任务说明、示例都放进 prompt，让模型续写出答案，这就是上下文学习。

### 8.1 纯编码器到底能干嘛？（理解类任务清单）

纯编码器只干一件事：**读懂整句文本，输出一串和输入等长的上下文向量，不生成新词**。工作流程是：输入完整句子 → 双向自注意力通读全文 → 每个 token 输出一个"动态上下文向量"（模型读完后的理解结果）→ 后面接一个很小的任务头（一层神经网络），把向量变成答案。所有计算一次性并行跑完，不循环、不逐词续写。

典型用途（全部属于理解类）：

1. **文本分类（整句打标签）**：如情感分析，取特殊标记 `[CLS]` 的向量 → 好评 / 差评；
2. **序列标注（每个 token 打标签）**：如命名实体识别（NER），"张三明天去上海" → 张三 = 人名、上海 = 地名；
3. **抽取式阅读理解**：读完"文章 + 问题"，从原文中标出答案片段——注意是"从原文抠出来"，不能自创一句全新回答，所以开放式聊天它做不了；
4. **语义相似度 / 句子向量**：输入两段文字生成向量，比距离判断是否同义。BGE、Sentence-BERT 就是纯编码器，专门用来做向量检索和 RAG 召回；
5. **预训练任务 MLM**：完形填空式自监督，"我吃 [MASK]" → 猜出被遮住的词是"苹果"。

### 8.2 解码器内部的两层注意力：掩码自注意力 vs 交叉注意力

一个 Decoder Block 里其实有两层注意力，这是最容易混淆的坑：

| 项目 | 掩码自注意力（第一层） | 交叉注意力（第二层） |
| --- | --- | --- |
| Q 来自 | 解码器自己 | 解码器当前生成状态 |
| K / V 来自 | 解码器自己 | 编码器的输出 |
| 因果掩码 | 有：只能看左边已生成的词 | 无：可以看编码器输出的全部位置 |

一句话：**解码器看"自己已经写出来的部分"是单向的；回看"编码器双向读完的原文"是无遮挡的。**

只有 Encoder-Decoder 架构才自带交叉注意力（原版 Transformer、T5、BART）。BERT 只有自注意力，GPT 只有掩码自注意力——它把交叉注意力删掉了，因为根本没有编码器可以访问。

### 8.3 为什么翻译必须用编码器 + 解码器？

翻译的两个环节对注意力的要求正好相反：

- **读源文（交给 Encoder）：必须双向。** 比如英文 "I saw a bank"，bank 是"河岸"还是"银行"，必须同时看它左右两边的上下文才能消除歧义；
- **写译文（交给 Decoder）：必须单向。** 译文要一个词一个词从左往右生成，如果生成"银行"时能偷看到后面的词，训练就变成直接抄答案，模型不需要学习推理。

所以原版翻译 Transformer 做成 Encoder-Decoder 的根本原因就是：**双向读原文 + 单向写译文，再靠交叉注意力让每一步生成都能无遮挡回看双向读完的原文。**

纯解码器（GPT）也能做翻译，但是"伪翻译"：它把"英文 + 提示词"拼成一条长序列，靠单向因果注意力读英文——读到 bank 的那一刻，右边的单词还看不见，无法立刻消歧，必须等后面的词出现才能修正理解。长难句、多义词更容易翻车，这是它做翻译的先天短板。

## 9. 预训练、微调、从头训练，到底什么关系？

**当时的困惑**：教程说微调只需要很少的数据就能达到不错效果，凭什么？

- **从头训练（Pre-training from scratch）**：所有权重随机初始化，需要海量语料和巨额算力，通常只有大公司做；
- **预训练（Pre-training）**：用**自监督**任务在大规模无标注文本上训练（CLM 预测下一个词 / MLM 预测被遮盖的词），标签自动从数据里产生，不需要人工标注，模型学到的是一般性的语言能力；
- **微调（Fine-tuning）**：用特定任务的**标注数据**对预训练权重做"二次训练"。因为模型已经掌握了通用语言知识，只需要少量数据就能适配新任务——这就是"站在巨人的肩膀上"。

这也解释了为什么 Hugging Face Hub 要共享模型权重：**把昂贵的预训练成果复用，避免每次训练都从头烧钱、烧能源。**

## 10. 为什么说注意力是 $O(n^2)$？长文本慢在哪？

**当时的困惑**：模型不是挺快的吗？为什么上下文一长就变慢、爆显存？

注意力分数矩阵是 $n \times n$ 的：每个 token 都要和所有 token 两两计算相似度，所以时间和内存都随序列长度**平方级**增长。这是 Transformer 处理长文本的核心瓶颈。

LLM 推理分两个阶段：

- **预填充（Prefill）**：一次性处理完所有输入 token，计算密集；
- **解码（Decode）**：逐 token 自回归生成，每个新 token 都要回顾所有历史 token，访存密集。

工程上的优化方向：

- **KV Cache**：缓存历史的 K、V，避免每个新 token 都重算前面全部内容，解码速度大幅提升，代价是显存随长度线性增长；
- **稀疏/滑动窗口注意力**：只让每个 token 关注窗口内的词，复杂度降到 $O(wn)$；
- **MQA / GQA（多查询/分组查询注意力）**：让多个头共享 K、V，减少访存量，GQA 被 Llama 等模型广泛采用；
- **FlashAttention**：矩阵分块 + 算子融合，减少中间结果写入显存；
- **PagedAttention**：把 KV Cache 像操作系统分页一样管理，减少拼接和显存碎片。

## 11. 温度、Top-k、Top-p、束搜索都是什么？

**当时的困惑**：教程讲采样策略时，一会儿 temperature 一会儿 top-p，这些参数到底调的是什么？

生成时，模型先输出词表里每个 token 的原始分数（logits），再转成概率并选择下一个词：

- **Temperature（温度）**：缩放 logits 的系数。$T > 1$ 更随机、更有创造力；$T < 1$ 更确定、更保守；
- **Top-k**：只从概率最高的 $k$ 个候选里选；
- **Top-p（核采样）**：只保留累计概率达到阈值 $p$ 的最小候选集合；
- **束搜索（Beam Search）**：同时维护多条候选序列，最后选整体概率最高的那一条，适合翻译等需要精确输出的任务。

记忆锚点：**temperature 管"发散程度"，top-k/top-p 管"候选范围"，beam search 管"全局最优"。**

## 12. 快速复习速查表

| 概念 | 一句话 |
| --- | --- |
| Transformer | 用自注意力建模序列的神经网络架构；注意力管"谁和谁相关"，位置编码管"谁在哪个位置" |
| Q / K / V | 查询 / 键 / 值：Q 提问，K 回答相关性，V 提供内容；输出 = 按权重对 V 加权求和 |
| $\sqrt{d_k}$ 缩放 | 防止点积随维度变大导致 softmax 饱和、梯度消失 |
| 多头注意力 | 多组线性投影并行做注意力，让模型从多个角度捕获关系 |
| Padding Mask | 屏蔽批处理时的填充 token |
| 因果 Mask | 下三角矩阵，防止解码器看到未来，训练时可并行 |
| 交叉注意力 | 编码器和解码器之间的桥梁：Q 来自解码器、K/V 来自编码器、无因果掩码；只有 Encoder-Decoder 有 |
| Encoder-only | 双向读懂文本、输出向量，做分类 / NER / 抽取式问答 / 句向量检索，不能生成 |
| Decoder-only | 因果注意力，适合生成任务，代表 GPT / Llama |
| Encoder-Decoder | 理解 + 生成，适合翻译/摘要，代表 T5 / BART |
| 翻译架构 | 源文必须双向读、译文必须单向生成，所以标准方案是 Encoder-Decoder；GPT 单向读源文，多义词易翻车 |
| 预训练 | 自监督学习通用语言能力，无需人工标注 |
| 微调 | 少量标注数据适配特定任务，复用预训练知识 |
| $O(n^2)$ | 注意力分数矩阵是 $n \times n$，长文本的瓶颈所在 |
| KV Cache | 缓存历史 K/V 加速解码，显存随长度线性增长 |
| Temperature / Top-k / Top-p / Beam | 生成时控制发散程度、候选范围、全局最优 |

## 结语

第一遍读不懂很正常，因为 Transformer 的知识是环环相扣的：不懂 Q/K/V 就看不懂注意力，不懂注意力就看不懂多头，不懂多头就理解不了为什么 BERT 和 GPT 长得不一样。我的学习建议：

1. **先会用，再弄懂**：先用 Transformers 库跑通一个 pipeline（比如情感分析），建立直觉后再回头啃原理；
2. **手推一遍小例子**：拿一个 5 个词的句子，手工算一遍 $5 \times 5$ 的注意力矩阵，很多"玄学"会瞬间消失；
3. **善用类比**：Q/K/V 用"检索"来理解，注意力输出用"加权平均"来理解；
4. **跑一遍手写代码**：教程第三章用 Pytorch 实现了完整的 Transformer block，跑一遍比看十遍文章有效。

最后，这份笔记也会随着我读第二遍、第三遍继续补充——学 Transformer 这件事，本身就是"注意力"不断迭代的过程。

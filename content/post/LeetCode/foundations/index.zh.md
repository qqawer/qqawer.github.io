刷 LeetCode 不能只记题解。真正可以迁移到新题上的能力，是看到题目后能回答三个问题：

1. 数据应该用什么结构保存？
2. 应该用什么算法处理？
3. 当输入规模变大时，时间和内存是否还能接受？

本文围绕这三个问题，整理一套算法入门知识框架。示例使用 Go，但分析方法适用于任何编程语言。

<!--more-->

## 一、先建立全局认识

可以把程序解决问题的过程类比成整理仓库：

- **数据结构**决定物品如何摆放，例如按顺序排、分类装箱或建立索引。
- **算法**决定人如何寻找和处理物品，例如逐个查找、折半查找或分区处理。
- **复杂度**衡量仓库越来越大以后，需要增加多少时间和空间。

同一道题往往有多种解法。复杂度分析帮助我们在结果都正确时，选择更具扩展性的方案。

## 二、为什么不能只看实际运行时间

最直接的评价方法，是让算法 A 和算法 B 在同一台电脑上运行，然后记录耗时与内存。但这种方法有明显局限：

- 结果受 CPU、内存、操作系统、编程语言和编译器影响。
- 小规模输入上的快慢，不能代表大规模输入上的表现。
- 穷举各种设备和输入规模，测试成本很高。

因此，我们通常不关心“这段代码准确运行了多少毫秒”，而关心：

> 当输入规模 \(n\) 逐渐增大时，算法所需时间和额外空间的增长速度。

这就是复杂度分析。它忽略机器差异和次要细节，保留影响增长趋势的主要部分。

## 三、时间复杂度

### 3.1 Big O 表示什么

时间复杂度通常用大 O 记号表示，例如 \(O(1)\)、\(O(n)\) 和 \(O(n^2)\)。

假设一段程序执行次数为：

\[
T(n)=3n^2+5n+20
\]

当 \(n\) 足够大时，\(n^2\) 是决定增长速度的部分，常数系数和低阶项不再重要，所以：

\[
T(n)=O(n^2)
\]

推算时可以记住三条规则：

1. **去掉常数系数**：\(O(2n)\rightarrow O(n)\)。
2. **只保留最高阶项**：\(O(n^2+n)\rightarrow O(n^2)\)。
3. **顺序执行取最大值，嵌套执行通常相乘**。

### 3.2 常见时间复杂度

从增长较慢到较快，大致为：

| 复杂度 | 常见场景 | 当 \(n\) 翻倍时 |
|---|---|---|
| \(O(1)\) | 数组按下标访问、哈希表平均查询 | 基本不变 |
| \(O(\log n)\) | 二分查找、平衡树查询 | 只增加一步左右 |
| \(O(n)\) | 遍历数组 | 约变为 2 倍 |
| \(O(n\log n)\) | 归并排序、堆排序 | 略多于 2 倍 |
| \(O(n^2)\) | 双层循环、比较所有数对 | 约变为 4 倍 |
| \(O(2^n)\) | 枚举所有子集 | 约变为平方 |
| \(O(n!)\) | 枚举所有排列 | 增长极快 |

复杂度并不等于实际速度。例如，执行一百万次固定操作仍是 \(O(1)\)，而只遍历 10 个元素仍是 \(O(n)\)。Big O 描述的是增长趋势，不是当前输入下的精确耗时。

### 3.3 看循环如何推算

#### 常数阶 \(O(1)\)

```go
func first(nums []int) int {
    return nums[0]
}
```

无论数组有多少个元素，都只访问一次。

#### 线性阶 \(O(n)\)

```go
func sum(nums []int) int {
    total := 0
    for _, num := range nums {
        total += num
    }
    return total
}
```

数组有 \(n\) 个元素，循环执行 \(n\) 次。

#### 平方阶 \(O(n^2)\)

```go
func allPairs(nums []int) {
    for i := 0; i < len(nums); i++ {
        for j := 0; j < len(nums); j++ {
            _ = nums[i] + nums[j]
        }
    }
}
```

外层执行 \(n\) 次，每次内层又执行 \(n\) 次，总次数为 \(n\times n\)。

#### 对数阶 \(O(\log n)\)

```go
func halve(n int) {
    for n > 1 {
        n /= 2
    }
}
```

假设初始值为 16，变化过程是：

\[
16\rightarrow 8\rightarrow 4\rightarrow 2\rightarrow 1
\]

执行 4 次后结束，而 \(4=\log_2 16\)。每次把问题规模减半，通常意味着 \(O(\log n)\)。

### 3.4 递归不能只看“是否除以 2”

分析递归时，要同时看两件事：

- **递归深度**：从根走到最深处有多少层。
- **每层节点数**：同一层一共调用了多少次。

#### 每次只调用一个 \(n/2\)：\(O(\log n)\)

```go
func oneBranch(n int) int {
    if n <= 1 {
        return 1
    }
    return oneBranch(n / 2)
}
```

递推式为：

\[
T(n)=T(n/2)+O(1)
\]

调用链只有一条，规模持续减半，因此一共有 \(\log_2 n\) 层，时间复杂度为 \(O(\log n)\)。

#### 每次调用两个 \(n/2\)：\(O(n)\)

```go
func twoHalfBranches(n int) int {
    if n <= 1 {
        return 1
    }
    return twoHalfBranches(n/2) + twoHalfBranches(n/2)
}
```

虽然每个子问题都减半，但每次会产生两个子调用：

\[
T(n)=2T(n/2)+O(1)
\]

递归树各层的节点数是 \(1,2,4,\dots,n\)，总节点数约为：

\[
1+2+4+\cdots+n=2n-1
\]

所以时间复杂度是 \(O(n)\)，而不是 \(O(\log n)\)。

#### 每次调用两个 \(n-1\)：\(O(2^n)\)

```go
func twoFullBranches(n int) int {
    if n <= 1 {
        return 1
    }
    return twoFullBranches(n-1) + twoFullBranches(n-1)
}
```

这里问题规模每次只减少 1，递归深度约为 \(n\)；每个节点又分出两个节点，第 \(k\) 层大约有 \(2^k\) 次调用：

\[
1+2+4+\cdots+2^n=2^{n+1}-1
\]

因此时间复杂度是 \(O(2^n)\)。

可以用一句话区分：

> `n/2` 决定树有多深，调用几次决定树有多宽；复杂度要计算整棵树，不能只看其中一个因素。

### 3.5 最好、最坏与平均情况

以下线性查找为例：

```go
func find(nums []int, target int) int {
    for i, num := range nums {
        if num == target {
            return i
        }
    }
    return -1
}
```

- 目标就在第一个位置：最好时间复杂度 \(O(1)\)。
- 目标在最后或不存在：最坏时间复杂度 \(O(n)\)。
- 目标等概率出现在任意位置：平均仍需检查约 \(n/2\) 个元素，即 \(O(n)\)。

LeetCode 默认通常讨论**最坏时间复杂度**，除非题目或答案特别说明。

## 四、空间复杂度

### 4.1 空间复杂度到底在算什么

空间复杂度描述输入规模增大时，算法所需**额外内存的峰值**如何增长。

这里有两个关键词：

- **额外内存**：通常不把题目本身的输入算进去，但新建的数组、哈希表和递归调用栈要算。
- **峰值**：看某一时刻同时占用了多少空间，不是把整个运行期间申请过的内存全部相加。

可以把它类比成停车场：一天内先后来了 1000 辆车，不代表需要 1000 个车位；真正决定停车场大小的是同一时刻最多停了多少辆车。

### 4.2 常数空间 \(O(1)\)

```go
func maxValue(nums []int) int {
    maxNum := nums[0]
    for _, num := range nums[1:] {
        if num > maxNum {
            maxNum = num
        }
    }
    return maxNum
}
```

不论输入多大，只额外保存少量变量，因此空间复杂度为 \(O(1)\)。循环执行 \(n\) 次不会自动带来 \(O(n)\) 空间，因为这些变量一直在被复用。

### 4.3 线性空间 \(O(n)\)

```go
func double(nums []int) []int {
    result := make([]int, len(nums))
    for i, num := range nums {
        result[i] = num * 2
    }
    return result
}
```

新数组长度随输入规模一起增长，因此额外空间为 \(O(n)\)。

哈希表记录 \(n\) 个元素、广度优先搜索的队列最多保存 \(n\) 个节点，也通常属于 \(O(n)\) 空间。

### 4.4 递归空间看最大调用深度

```go
func factorial(n int) int {
    if n <= 1 {
        return 1
    }
    return n * factorial(n-1)
}
```

调用 `factorial(n)` 时，前一个函数必须等待后一个函数返回。调用栈最多同时保留 \(n\) 层，所以：

- 时间复杂度：\(O(n)\)
- 空间复杂度：\(O(n)\)

再看前面的双分支递归：

```go
func twoHalfBranches(n int) int {
    if n <= 1 {
        return 1
    }
    return twoHalfBranches(n/2) + twoHalfBranches(n/2)
}
```

它虽然一共创建约 \(n\) 次调用，但程序会先完成左分支，再处理右分支；同一时刻调用栈里只有一条从根到叶子的路径。因此：

- 时间复杂度：\(O(n)\)
- 空间复杂度：\(O(\log n)\)

这再次说明：空间复杂度看的是**同时存在的峰值**，而不是累计调用次数。

### 4.5 原地算法不一定绝对不占内存

“原地算法”通常表示只使用 \(O(1)\) 额外空间，但实际分析还要留意：

- 递归版快速排序需要调用栈。
- Go 的切片只是对底层数组的描述，新切片不一定复制元素。
- 返回结果所占空间是否计入，可能因题目约定而不同。

答题时最好明确说明：“若不计算返回值，则额外空间为……”“递归调用栈需要……”，比只写一个结论更严谨。

## 五、迭代、递归与分治

### 5.1 迭代

迭代通过循环重复执行代码。优点是额外开销小、执行过程直观；缺点是处理树和嵌套结构时，代码有时不如递归自然。

### 5.2 递归

递归函数调用自身，一般包含：

1. **终止条件**：什么时候停止。
2. **递归关系**：如何把原问题缩小。
3. **返回过程**：子问题答案如何组成原问题答案。

写递归最常见的错误是缺少终止条件、问题规模没有缩小，或者重复计算大量相同子问题。

### 5.3 分治

分治是一种思想：把大问题拆成相互独立的小问题，分别解决后再合并。

典型流程是：

1. **分解（divide）**：将原问题拆小。
2. **解决（conquer）**：递归解决子问题。
3. **合并（combine）**：组合子问题的答案。

归并排序就是典型例子：不断把数组分成两半，分别排序，最后合并。递归深度是 \(O(\log n)\)，每层合并总共处理 \(n\) 个元素，因此时间复杂度为 \(O(n\log n)\)。

需要注意：递归是一种代码实现方式，分治是一种解决问题的思想。分治经常用递归实现，但递归不一定是在做分治。

## 六、常见数据结构

| 数据结构 | 核心特点 | 常见操作复杂度 | 典型应用 |
|---|---|---|---|
| 数组 / 切片 | 连续存储、支持下标访问 | 查询 \(O(1)\)，中间插删 \(O(n)\) | 双指针、滑动窗口、前缀和 |
| 链表 | 节点通过指针连接 | 已知节点插删 \(O(1)\)，查找 \(O(n)\) | 反转链表、合并链表 |
| 栈 | 后进先出 | 入栈、出栈 \(O(1)\) | 括号匹配、单调栈、DFS |
| 队列 | 先进先出 | 入队、出队 \(O(1)\) | BFS、任务调度 |
| 哈希表 | 键映射到值 | 平均查询、插入 \(O(1)\) | Two Sum、计数、去重 |
| 树 | 层级关系 | 取决于树高 | 目录、搜索、递归遍历 |
| 堆 | 快速取得最小值或最大值 | 取堆顶 \(O(1)\)，插入/删除 \(O(\log n)\) | Top K、优先队列 |
| 图 | 表示多对多关系 | 遍历通常 \(O(V+E)\) | 路径、依赖、网络关系 |

选择数据结构时，不要只问“它能不能存”，还要问“题目最频繁的操作是什么”。例如，需要频繁判断元素是否存在时，哈希表通常比每次扫描数组更合适。

## 七、常见算法思想

### 7.1 搜索

- **线性搜索**：逐个检查，时间复杂度 \(O(n)\)。
- **二分搜索**：利用有序性每次排除一半，时间复杂度 \(O(\log n)\)。
- **深度优先搜索（DFS）**：沿一条路径尽量深入，适合递归、连通性和路径枚举。
- **广度优先搜索（BFS）**：逐层扩展，适合无权图最短路径。

### 7.2 排序

- 冒泡、选择、插入排序通常为 \(O(n^2)\)。
- 归并、堆排序稳定在 \(O(n\log n)\) 量级。
- 快速排序平均为 \(O(n\log n)\)，最坏为 \(O(n^2)\)。

排序的意义不只是改变顺序。很多题排序后才能使用双指针、贪心或二分，从而把后续处理从 \(O(n^2)\) 降到 \(O(n\log n)\)。

### 7.3 回溯

回溯可以理解为“做选择 → 继续探索 → 撤销选择”。它适合排列、组合、子集、棋盘搜索等需要枚举解空间的问题。

```text
选择一个候选
├── 满足条件：继续向下搜索
└── 搜索结束：撤销选择，尝试下一个候选
```

回溯的复杂度通常较高，优化关键在于**剪枝**：尽早排除不可能得到答案的分支。

### 7.4 动态规划

动态规划适合具有“重叠子问题”和“最优子结构”的问题。核心不是背公式，而是明确：

1. `dp[i]` 表示什么？
2. 状态如何从更小状态转移？
3. 初始状态是什么？
4. 按什么顺序计算？
5. 最终答案在哪里？

递归重复计算同一问题时，可以先考虑记忆化搜索；看清状态依赖后，再改写为自底向上的动态规划。

### 7.5 贪心

贪心算法每一步都选择当前看来最优的方案，希望最终得到全局最优解。它通常高效，但必须证明局部最优选择不会破坏全局最优解。

如果只能凭直觉说“每次拿最大的就行”，却无法给出交换论证、反证或题目结构依据，就要警惕贪心可能是错的。

## 八、LeetCode 解题步骤

拿到题目后，可以按以下顺序思考：

1. **确认输入、输出和边界**：空数组、重复元素、负数、溢出是否存在？
2. **先想暴力解法**：它帮助确认问题本质，也提供正确性基线。
3. **计算暴力复杂度**：结合数据范围判断是否会超时。
4. **寻找重复工作**：能否用哈希表、前缀和或动态规划保存结果？
5. **寻找特殊性质**：是否有序？能否二分、双指针或滑动窗口？
6. **选择数据结构**：高频操作是查询、插入、取极值还是逐层遍历？
7. **写出不变量**：循环或递归过程中，始终成立的条件是什么？
8. **实现并验证边界**：用最小输入、极端输入和重复值手动走一遍。
9. **写清复杂度**：说明 \(n\) 表示什么，并分别分析时间和额外空间。

## 九、一个完整示例：Two Sum

题目：给定整数数组 `nums` 和目标值 `target`，返回和为目标值的两个元素下标。

### 暴力解法

枚举所有数对：

```go
func twoSumBruteForce(nums []int, target int) []int {
    for i := 0; i < len(nums); i++ {
        for j := i + 1; j < len(nums); j++ {
            if nums[i]+nums[j] == target {
                return []int{i, j}
            }
        }
    }
    return nil
}
```

- 时间复杂度：\(O(n^2)\)
- 额外空间复杂度：\(O(1)\)

### 哈希表优化

遍历到 `nums[i]` 时，检查此前是否见过 `target - nums[i]`：

```go
func twoSum(nums []int, target int) []int {
    seen := make(map[int]int)

    for i, num := range nums {
        complement := target - num
        if j, ok := seen[complement]; ok {
            return []int{j, i}
        }
        seen[num] = i
    }

    return nil
}
```

- 时间复杂度：平均 \(O(n)\)
- 额外空间复杂度：\(O(n)\)

这个优化体现了典型的“空间换时间”：用哈希表保存已经看过的元素，把内层线性查找降为平均 \(O(1)\) 查询。

## 十、容易混淆的结论

1. **两个连续循环不是 \(O(n^2)\)**：若各执行 \(n\) 次，总量是 \(n+n=2n\)，所以是 \(O(n)\)。
2. **两个嵌套循环才通常相乘**：\(n\times n=O(n^2)\)。
3. **每次除以 2 不一定是 \(O(\log n)\)**：还要看每次产生多少个递归分支。
4. **递归时间和空间可能不同**：调用总数决定时间，最大调用深度通常决定栈空间。
5. **哈希表操作不是绝对 \(O(1)\)**：通常说的是平均复杂度，极端冲突下可能退化。
6. **复杂度更优不代表任何时候都更快**：小输入、缓存局部性和常数开销也会影响实际表现。
7. **空间复杂度不是累计申请量**：关注运行过程中同时占用的最大额外空间。

## 十一、学习路线

建议按下面的顺序练习：

1. 数组、字符串、哈希表
2. 双指针、滑动窗口、前缀和
3. 链表、栈、队列
4. 二分查找、排序
5. 二叉树、DFS、BFS
6. 堆、并查集、图
7. 回溯、贪心、动态规划

每做完一道题，不妨留下四行复盘：

```text
题型：
关键不变量：
时间复杂度：
空间复杂度：
```

长期来看，能准确归类题型、说清正确性和复杂度，比记住某一道题的代码更重要。
